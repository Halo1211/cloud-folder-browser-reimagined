# Bug audit — October 1, 2026

This additional audit examined a local Cloud Folder Browser Reimagined checkout
and preserved all changes from previous audit passes. It used `diagnosing-bugs`,
`security-review`, and `verification-loop`.

## Results

- Baseline: **389 passing tests**, zero failures, and zero skipped tests.
- Added **36 test cases**: **26 were run and failed before their fixes**, with
  10 controls or compatibility checks. Failing case counts are not independent
  bug counts; theories exercise several variations of the same defect.
- Final full suite: **425 passing tests**, zero failures, and zero skipped tests,
  completing in 26 seconds.
- Release solution build with `TreatWarningsAsErrors=true`: **zero warnings and
  zero errors**. This includes configured C# type and analyzer checks. Coverage
  was not measured.
- `git diff --check` passed. A limited source/config scan for private-key and
  OpenAI-token patterns found no matches; it does not cover every kind of secret.
- NuGet advisory check with `--vulnerable --include-transitive --format json`:
  exit code 0, with no vulnerable packages reported in six projects. Copied
  vendor code is outside the package advisory check.
- `UiSnapshots` generated **25 images** in `artifacts/audit-ui-tenth-pass/`.
  The main window, sync preview, and download history were inspected visually;
  no layout regression was visible in those three views.

## Fixes

| Area | Trigger and previous impact | Corrected behavior |
| --- | --- | --- |
| Download credentials | Basic Authentication was installed on the client's default headers, exposing source credentials to resolved URLs on other origins. | Credentials are attached per request only when scheme, host, and port match the source URL. Same-origin resolvers and AllSync direct downloads remain authenticated. |
| Cookies and redirects | Automatic redirects forwarded manual Cookie headers to unrelated hosts or paths outside a cookie's scope. | CookieContainer checks domain, path, and Secure on every request and redirect. Downloads, the WebDAV adapter, and portable/legacy AllSync browsing use it. Old session cookies are removed during refresh. |
| Non-file metadata responses | HTTP 204/205/206 supplied metadata as though they described a complete file, locking in empty or partial lengths. | Only GET 200 supplies complete-file metadata. Other responses retain unknown size and the original download URL. |
| Challenge-page metadata | Redirects to HTML login pages stored the page's length and login URL as the identity of a `.bin` file. | HTML pages for non-HTML file names do not supply metadata. Actual `.html`/`.htm` files and valid empty files remain supported. |
| Retry checksums | A failed full response's checksum survived a later full response even when the new representation supplied none. | Each full response replaces the remembered checksum, including clearing an absent checksum. Available new checksums still validate. |
| Content-MD5 after restart | A resume request returning 200 restarted from zero but skipped Content-MD5 because `.part` initially existed. | Every 200 response checks Content-MD5. A 206 content hash is still not interpreted as a whole-file hash. |
| Checksum format | Decodable Base64 with the wrong MD5/SHA-256 length caused valid downloads to fail. | MD5 requires 16 bytes and SHA-256 requires 32. Malformed lengths are ignored consistently with invalid Base64. |
| Checksum selection | The first recognized Digest algorithm could choose MD5 ahead of available SHA-256. | Valid SHA-256 takes priority independently of header order; MD5 remains a fallback. |
| Provider matchers | Dropbox/Google accepted FTP by hostname and threw on relative URIs. | Matchers accept only absolute HTTP(S) URIs. |
| DNS cancellation | Literal IP and localhost lookups succeeded with a pre-canceled token; cache paths also bypassed the initial check. | UDP and secure resolvers check cancellation before literal, localhost, cache, or transport paths. |
| Sync cancellation | An empty selection completed its sync plan despite a pre-canceled token. | Plan construction checks the token at entry. |
| Sync preview | Rename-target evaluation mutated the plan before Continue, and Reset suggested discarded the initial rename target. | Validation leaves the plan unchanged. Reset restores the initial suggested action and name; mutation happens during Apply. |
| Active accounts | Upserting `IsActive=true` with `makeActive=false` left another account active for the same provider. | That upsert leaves at most one active account for the provider. |
| WebDAV paths | ListShared ignored its requested subfolder and always sent PROPFIND to the share root. | Requested segments are URI-encoded and appended; `+`, Unicode, and root paths work. The requested parent collection is excluded from returned children. |
| WebDAV passwords | ASCII Basic header encoding replaced characters in passwords such as `päss_日本` with `?`. | ListShared uses UTF-8, consistent with AllSync downloads. |

## Reproduction and coverage

New cases are in `CloudFolderBrowser.Tests/TenthPassAuditTests.cs` and the
`TenthPass_` methods in `RealDownloadIntegrationTests.cs`. Reproductions use real
TCP loopback servers, captured requests, temporary DPAPI account fixtures, and
STA WinForms tests. They require no user cloud accounts or credentials.

The initial loop reproduced 21 failures among 24 cases. Two additional cookie
redirect cases failed. Account/WebDAV loops proved duplicate active accounts,
ignored paths, and changed password encoding. After the fixes, all 36 targeted
cases passed. Controls cover same-origin authentication, actual HTML and empty
files, SHA-256 selection, cookie domain/path/Secure restrictions, old-cookie
removal, WebDAV integration, and authentication challenges after redirects. The
existing WebDAV adapter did not expose credentials to a redirected server's
challenge, so its authentication mechanism was retained.

The existing suite also verifies transfers/resume/segments, scheduling,
direct/debrid routing, local/remote checksums, account/history/cache/backup
persistence, provider parsing, path sanitization, ZIP/PAR2/external processes,
and UI workflows/rendering. No dependencies or saved-data formats changed.

## Verification limits

OAuth/MEGA login, every live provider, external endpoints/proxies, a live
FlareSolverr service, and actual JDownloader imports were not tested end-to-end.
Cookie refresh tests check removal/installation in CookieContainer, not live
FlareSolverr. Render checks do not cover every DPI or resolution. Cross-session
single-stream `.part` resume without a remote version validator retains the
representation-identity limitation described in the previous audit. This audit
covers many modules but does not prove the program has no remaining bugs.
